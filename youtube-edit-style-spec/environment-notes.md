# このMacの環境知見

**このファイルは何を扱うか**: このMac固有の実測済み制約（ffmpeg機能欠如・iPhone MOV・HDR・フォント・レンダリング性能・強調テロップの視認性数値・音声TP問題・ズームエフェクト実装・被りQC）。
**いつ読むか**: ffmpeg/Pillowでの合成・レンダリング工程に入る前。実装が「なぜか遅い／なぜか不発」の症状に遭遇したときの一次参照。

## このMacの環境知見（実測）

- **ffmpegにlibass/drawtextなし** → 字幕焼き込みはPillowでPNG生成→`overlay`フィルタ方式（enable='between(t,..)'）
- **iPhone .MOV** → 必ず `ffmpeg -map 0:v:0 -map 0:a:0 -c copy -movflags +faststart` でクリーン変換。**回転メタデータ(rotation=-90等)を必ず確認**し正しい向きで処理
- **HDR素材（Dolby Vision/HLG）** → zscale非搭載のため `colorspace=all=bt709:iall=bt709:fast=1` でSDR化＋出力に `-color_primaries/-color_trc/-colorspace bt709` 明示。color_transferがbt709になったことをffprobeで検証
- 日本語フォント: NotoSansJP（~/Library/Fonts/）またはヒラギノ（/System/Library/Fonts/）
- whisperはCPU推論で実時間の6〜10倍。複数エージェント並行時はCPU競合でさらに遅延（正常）
- **ffmpeg 8.0.1のselect/aselectフィルタは不発**（カット編集に使わない）→ trim/atrim＋concat方式を使う（DJI_0029で実証）
- **フルキャンバス透過PNGの多段overlayは激遅（~1fps）** → PNGを実描画領域だけにbboxクロップしてoverlay座標指定すれば~29fpsに改善（showcase実証）
- **`-loop 1`入力（Ken Burns用静止画等）を含むフィルタグラフは出力が終端しない** → 出力側に `-t` キャップ必須（showcase実証）
- **多分割concat＋fps量子化のタイムラインドリフト**: セグメント毎のフレーム量子化誤差が累積し90秒地点で最大+0.8s程度ずれる。焼き込み済み字幕に後から要素（強調テロップ等）を同期させる場合、名目タイムラインを信用せず**実フレーム計測**（テンプレート照合等）で位置合わせする（showcase v2実証）
- **強調テロップの選定規則**: 重要語・固有名詞・意外な主張のみ／1トピック1回（Revealと同トピックの重複も禁止）／**同時刻の通常字幕と同一文言の復唱禁止**（字幕の消滅実時刻+0.12s以降に配置）
- **強調テロップの視認性（確定数値・2026-07-11チューニング）**: フォント92／黒フチ12px／ドロップシャドウ常時（offset 4,4px・blur 3・不透明度40%）／**背景輝度>0.65（テロップ矩形領域の実フレーム計測）なら半透明黒座布団（不透明度40%・角丸20px）を自動追加**。明背景（窓・白壁）でも可読なことを実測確認済み
- **ネイティブAACエンコーダはTrue Peakが+1.3dB程度オーバーシュートする** → `aac_at`（AudioToolbox）＋192kHzオーバーサンプリングのリミッター（`alimiter` は `level=false` 必須）で解決（DJI_0029で実証）。さらに**合成・変換段では音声を再エンコードせず`-c:a copy`必須**（aac_at再エンコードでもTP+0.5dB悪化を実測）
- **ズーム系エフェクトの正しい実装（スタイル検証で確定）**: ①cropフィルタのw/hはper-frame再評価されず、x/y式の`in_w/in_h`も初期化時に定数化される→時間可変式は`t`を含む明示式で書く（`x='(1920*Z(t)-1920)/2'`等）②**アンカーは下端固定**（`y='1080*Z(t)-1080'`）にすると下部字幕が数学的に見切れない ③**全オーバーレイはズームの後段で合成**（テロップはパンチインに追従しない実バラエティ標準・見切れゼロを構造保証）
- **スタイル変換ジョブの入力は「字幕焼き込み前のクリーンベース」必須**: dist最終品を入力にすると二重字幕になる。クリーンベースが無い場合はcuts.jsonから元素材をtrim+concatで再構築（Vlog検証で実証）
- **レンダリング前の被りQCゲート必須**: `~/Documents/編集作業/overlap_qc/overlap_qc.py`（マニフェスト機械解析＋アルファ実描画bbox交差＋concatフレーム量子化時刻再構成）を書き出し前に実行し、交差率5%超をゼロにしてからレンダリングする。許容パターン=全画面不透明カードによる完全遮蔽／安全コンテナ内包のみ
- **被り予防の設計規則（被り総点検で確定）**: ①折返し済み行データを別スタイルに流用禁止（幅前提が違う→必ず再折返し） ②常駐UI（サイドバー等）は「字幕安全幅」を事前定義（例: biztalkサイドバー時は字幕最大628px/ネームプレート同時は484px） ③**どの折返し実装にも禁則処理を必ず入れる**（行頭の。、！？」等は前行末へ送る。幅は+1文字分まで超過許容）
