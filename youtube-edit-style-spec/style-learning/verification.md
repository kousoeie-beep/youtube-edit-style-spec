# スタイル学習: 検証（手順5）の落とし穴

**このファイルは何を扱うか**: テスト適用時の測定原理の落とし穴2種（オーバーレイのカット誤検知、無音率の測定下限）と、検証前のLRA・検証用音源の事前確認手順。
**いつ読むか**: スタイル学習の手順5（検証）でプリセットをテスト素材に適用し、数値目標との一致/不一致を判定するとき。

5. 検証: テスト素材1本にプリセットを適用し、参考動画とのフレーム比較で寄せ度を確認

### 【最重要】検証クリップでの測定には2つの原理的な落とし穴がある（2026-07-26に判明）

**落とし穴1: `cuts_per_min` はオーバーレイの境界を誤検知する**
全画面〜大型のオーバーレイを重ねると、**scene検出はオーバーレイの出入りをカットとして拾い、
その配下にある実際の映像カットは隠れて検出されなくなる**。
実例: documentary_cinematicの検証で cuts 12.10（目標7.21）と出たが、検出6件が
**すべてオーバーレイ切替時刻と完全一致**していた＝素材のカットを1件も測れていなかった。
→ **対策**: ①オーバーレイを外した「クリーンベース」でカット率を測る
  ②オーバーレイ入りで測った値は「参考値」とし、定義値との一致/不一致を判定に使わない
  ③検出時刻とオーバーレイ切替時刻の一覧を突き合わせ、一致するものを除外してから算出する

**`fps=1/N` のフレーム抽出は正確**（2026-07-26に「B-frame混在時に約1秒ずれる」という報告があり検証したが、**再現しなかった**）。
B-frameを含む合成動画（I,B,P,B,P...）でも `fps=1/2` は PTS 0/2/4/6/8 を正確に返し、
`-ss` 直接シークとのピクセル差分も1〜2px（エンコード誤差レベル）だった。4スタイルで確認済み。
**疑わしいときは以下で自分で確かめること**（推測で「ずれている」と判断しない）:
```bash
ffmpeg -i <動画> -vf "fps=1/2,showinfo" -frames:v 5 -f null - 2>&1 | grep -oE "pts_time:[0-9.]+"
# 期待値 0,2,4,6,8 と一致するか
```
※ただし **`-ss` を入力側（`-i` の前）に置くとキーフレームスナップで時刻がずれる**のは別問題として実在する。
  こちらは既知でありスタイル学習の手順でも `fps=1/N` を使う理由になっている。

**落とし穴2: 無音率には「クリップ長で決まる測定下限」がある**
`silencedetect d=0.5` は0.5秒未満の無音を検出しない。したがって
**測定可能な最小無音率 = 0.5秒 ÷ クリップ長**
（この公式と登録前ゲートでの使い方は [schema.md](schema.md) が正本。ここでは検証時の実務として再掲する）。
- 30秒クリップ → 下限 **1.67%**
- 100秒クリップ → 下限 0.5%
**目標値がこの下限を下回るスタイルは、そのクリップ長では原理的に検証不能**。
該当例（30秒クリップの場合）: wipe_explainer(0.45-1.08%) / documentary_cinematic(0.74%) /
documentary_immersive(0.13-0.89%) / documentary_investigative(0.26-1.22%) /
field_interview(0.86-1.29%) ＝ **ドキュメンタリー系のほぼ全て**
→ **対策**: ①目標無音率が低いスタイルは検証クリップを長くする（目安: 0.5 ÷ 目標率 秒以上）
  ②短いクリップで測るなら `d` を下げる（例 `d=0.2`）が、**定義値は d=0.5 で測った値なので
    そのままでは比較できない**。下げた場合は必ずレポートに明記する
  ③どちらもできない場合は「クリップ長の制約により無音率は検証不能」と明記する
- **検証用音源のLRAが目標に届くかを事前に確認する**（2026-07-26 japan_vlog検証で判明）。
  `japan_vlog` は LRA 19.0（ノーマライズ厳禁）が特性だが、**検証用音源のLRAが元々10.9しかなく、
  どんな処理をしても到達不可能**だった（実測9.2＝素材からわずかに縮んだだけで処理は適切）。
  **「実装が悪い」と「素材が足りない」を取り違えないため、着手前に素材のLRAを測る**:
  ```bash
  ffmpeg -i <素材> -af ebur128=peak=true -f null - 2>&1 | grep -E "^ +(I|LRA):"
  ```
  参考値: `DJI_0029/work/audio_16k_mono.wav` = I -29.8 / **LRA 10.9**、
          `DJI_0029_vlog/work/audio_graded.m4a` = I -17.0 / **LRA 8.1**
  → **LRA 12以上を要求するスタイル（japan_vlog 19.0 / documentary_startup_journey の一部変種 12.3-12.4）は
    現有素材では音響面を検証できない**。該当する場合は「素材の限界により音響未検証」と明記すること。
- **検証用音源は「発話に間のあるもの」を使う**（2026-07-25〜26の適用検証4本で繰り返し詰まった）。
  `DJI_0029_vlog/work/audio_graded.m4a` は環境音が密で **-35dBを一度も下回らず、silencedetectが0件**になるため
  **無音率（gap_keep_sec / filler_policy）の検証が原理的に成立しない**。
  代わりに **`DJI_0029/work/audio_16k_mono.wav`（133秒・無音率1.35%・3区間）** を使えば測定できる。
  無音率はスタイル選定の第一軸（ドキュメンタリー0.13-1.22% ↔ 解説系20-24%）なので、
  **これを測れない検証は「音響面は未検証」と明記すること**

> LUFS/LRAの交換関係の詳細実測データは [audio-pipeline.md](../audio-pipeline.md) を参照。
