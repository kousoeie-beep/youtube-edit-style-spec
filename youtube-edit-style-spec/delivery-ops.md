# 納品運用ルールと品質実績

**このファイルは何を扱うか**: 消失事故対策（nice値降格・scratchpad揮発性・作業ディレクトリ）と納品手順、および過去パイロットの品質実績（参考基準）。
**いつ読むか**: ジョブ開始時（作業ディレクトリ決定・ディスク残量確認）と書き出し・納品時。

## 納品運用ルール（消失事故対策・必須）

- **`nohup ... &` のバックグラウンド実行は nice 5 に降格される**（2026-07-26に実測確認。前景は nice 0）。
  **高負荷時（load 20以上）は nice 5 のプロセスがCPUをほとんど割り当てられず、事実上停止する**。
  並列検証中に「PNG 1枚の生成に2分」という異常な遅さが発生し、当初「並列度が高すぎる」と誤診断したが、
  真因はこれだった。**重いレンダリング・PNG生成は前景で実行する**（ハーネスは120秒で自動的に
  バックグラウンド化するが、その場合も nice 0 が維持される）。
  ```bash
  # 悪い: nice 5 に降格し高負荷時に進まない
  nohup python3 build.py > log 2>&1 &
  # 良い: nice 0 のまま。120秒超なら自動でバックグラウンド化される
  python3 build.py 2>&1 | tail -20
  ```
- **scratchpad（/private/tmp）は1日どころか数時間で消えることがある**（2026-07-10に一晩で2回のパージを実測。macOSはディスク逼迫時に積極的にパージする）
- **作業ディレクトリはtmpに置かない**: 動画編集ジョブの作業場所は `~/Documents/編集作業/<案件名>/` を使う（素材コピー・中間生成物・distすべて）。ジョブ完了後にこうすけの指示があれば削除
- 完成動画・サムネ・主要ログは書き出し後すぐ `~/Downloads/<案件名>納品/` へコピー
- **開始前にディスク残量を確認**（`df -h /`）。素材サイズ+3GB未満の空きなら停止して報告（4K素材はコピー+中間生成で膨らむ）
- 未pushのgit作業をscratchpadに放置しない
- 完成報告には納品先パス・尺の変化・カット判断・QC集計・フォールバック一覧・処理時間を含める

## 並列作業時の注意（2026-07-27に実害発生）

**複数エージェントが同時にこのスキルを編集すると、後から書いた側が先の変更を上書きして消す。**
実例: 色ロール適用中にSKILL.md分割が並行して走り、分割側が読んだ後に追記された15行
（`color_shadow` が15/15スタイルでnullという発見と共通デフォルト規定）が消失した。
git履歴を追って復元したが、**気づかなければそのまま失われていた**。

**並列で走らせるときの規律**:
- **担当ファイルを重複させない**（Brief に「指定ファイル以外は触らない」を明記する）
- **本体（SKILL.md）と leaf を同時に編集させない**
- 長時間かかる作業（分割・大規模リファクタ）の最中は、**同じファイルへの追記を止める**
- 完了後は必ず `git diff` で「消えた行が無いか」を確認する（追加行だけ見ていると気づけない）
- **`git add` にディレクトリを渡さない。ファイルを列挙する**（2026-07-27に2件目の実害）

### 2件目の実害: コミットが他人の成果物を巻き込む

`git add .claude/skills/youtube-edit-style-spec/` と広く指定したところ、**並列実行中の
エージェントが書き上げた直後の `fonts/meta.json`・`fonts/README.md`（191フォントの
ライセンス索引）が、まったく無関係な「導線修正」コミット2本に紛れ込んだ**。

上書き事故と違い**内容は失われない**ため git diff では検出できない。壊れるのは履歴の
可読性で、後からログを読んでも索引がどこで入ったのか永久に分からなくなる。

- 検出方法: コミット直後に `git show --stat` を見て、**メッセージに書いていない
  ファイルが入っていないか**を確認する
- 復旧: 未pushなら `git reset --soft <巻き込み前>` → 内容ごとに add し直して再コミット。
  作業ツリーは触らないので安全。`git diff <旧HEAD> HEAD --stat` が空になれば
  「メッセージだけ直り内容は不変」を証明できる
- pushしてしまった後は履歴を書き換えられない。**コミット前に `git status` を見る**のが唯一の防壁
