## 一目でわかる違い

- **カット律の対極**: `educational_explainer`(0.08/分・ほぼ無カット) ↔ `business_talk`(11.5/分・高頻度リアクションカット)。同じ「トーク」でもジャンルで100倍以上の差。
- **視覚リズムとハードカットの乖離が最大**: `kirinuki`はカメラカット0.36/分なのに視覚リズム36.9/分＝カットでなくテロップ切替だけで体感テンポを作る典型例。
- **テロップ密度の対極**: `kirinuki`(全発話100%カバー) ↔ `japan_vlog`(バイリンガル控えめキャプションのみ、装飾色ゼロ)。
- **LUFS/LRAは3クラスタ**: 会話標準(`business_talk`/`kirinuki`/`educational_explainer` = -15前後・LRA5前後) ↔ バラエティ(`entertainment_variety` = -19.1・LRA9.8) ↔ 静音広ダイナミクス(`japan_vlog` = -22.8・LRA19.0、ノーマライズ厳禁)。
- **無音ポリシーの3極**: 詰める(`business_talk`/`entertainment_variety`) ↔ 短い間欠を残す(`kirinuki`/`japan_vlog`) ↔ 積極的に残す(`educational_explainer`、総尺の約2割が無音でも許容)。

- **無音率が「ドキュメンタリー系 vs 解説系」の決定的な識別指標**（2026-07-25の実測10本で判明）: ドキュメンタリーA〜C系は0.13-1.22%＝音楽とナレーションで間を埋め続ける。対して解説系の`ai_news_weekly`は20-24%、`educational_explainer`も約2割が無音＝発話の間を残す。**編集時のfiller_policyとBGM方針が正反対になる**ため、スタイル選定で最初に判断すべき軸。
- **例外はD系（日本語ナレーション）**: D1(D1・国内TV報道)は8.14%と、ドキュメンタリーでありながら解説系寄りに間を残す。ただし同じ日本語でもD2(D2翻訳版)は2.71%。**効く変数は言語ではなく「制作元」**（国内TV局制作か、海外制作の翻訳版か）。
- **`documentary_cinematic`は1スタイル内で3変種に割れる唯一の例**: 顔出しホスト型/ナレーションのみ型/専門家インタビュー型でLUFSが-18.3〜-24.7（6LU超）、cutsが7.21〜16.37と乖離する。`screen_tutorial`の3クラスタと同様、**サブパターンを先に選ばないと数値が意味を持たない**タイプ。
- **`documentary_startup_journey` だけが「作り込むほど質が下がる」**: 他14スタイルは全て作り込む方向に最適化されているが、この系統は**作り込みすぎると「応援」ではなく「消費」になる**。手ブレ・言い淀み・未完成のプロダクト画面を意図的に残す（**無音率0.44-30.04%を許容**）。n増でこの逆説が裏付けられ、build in public 6本中5本が無音5-30%・カット0.09-2.51/分という極端な生々しさに分布した（きれいに編集された1本の方が例外）。生々しさとシネマティックの**中間が最も弱い**ため、どちらかに振り切ること。
- **`documentary_startup_journey` だけが連載構造を前提とする**: 他14スタイルは単発完結だが、この系統は**時間の経過そのものが物語の骨格**。「DAY 3」全画面カード（英語圏build in public）／「3歳、原体験のルーツ」の人生年表章立て（日本の密着）という2つの時間刻み方が実測された。`business_talk`（BT1＝ピッチの一発勝負）との最大の差分がここ。
- **日本の「1日密着ドキュメンタリー」には確定した装置セットがある**（`documentary_startup_journey` の `variant_field_interview`・n=3で確認）: ①全編フル字幕 ②チャンネルロゴ常駐 ③行動ラベル/章タグを画面隅に常駐（「掃除終了」「今後の展望」＝時系列の実況） ④「Q.」アイコン付き質問カード ⑤人物ステータス/名前テロップ ⑥末尾CTA。**S1・S2・S3の3本すべてに存在**し、無音率も0.86-1.29%と安定。**そのまま実装仕様として使える唯一の変種**。なお `business_talk`（BT1）の「志願者ステータス常駐」、`documentary_immersive` B3（B3）の「ステータスカード」も同じ発想で、**日本のTV/密着系に共通する情報設計**と言える。
- **同一チャンネルでも数値は再現しない**（P-sample 2本で実証）: レターボックス・黒背景カード・ブランドロゴ・黄キーワード抜きという**意匠は完全に一致**したが、cuts_per_minは6.10→17.42（2.9倍）、無音率5.44%→13.68%と乖離した。`wipe_explainer` のn増と同じ構図で、**スタイル適用時に踏襲すべきは意匠であって数値ではない**という原則が2ジャンルで確認された。
- **`screen_tutorial`は強調色がジャンル外れ値**: 他5ジャンルが黄・赤・青など多色を役割別に使い分けるのに対し、`screen_tutorial`は「操作対象＝赤」一色にほぼ統一（基準プリセット既定値の「強調=黄」からの明確な差分）。
- **`screen_tutorial`はカット律が単一ジャンル内で最大3クラスタに分岐**: 純粋PC画面共有(0.17-1.7、ST1型)↔顔出し⇄画面共有の交互切替(3.8-5.5、ST2仮想デスクトップ型)↔イラスト解説ハイブリッド(11.6、ST2 Windows動作軽量化型)。他5ジャンルは概ね1本の数値で代表できたが、本ジャンルはサブパターンごとにapply_notesで使い分けを明記する必要があった。

### R8→R9で分かった、失敗の質の変化

R9では**宣言した修正はほぼ全部効いた**（cinematic 4/4・investigative 5/5・
narrated の variant と散文訂正・startup 5/6・tutorial 3/3）。
それでも6ファイルとも「不可」だったのは、**別の型の欠陥に移ったから**である。

| 周 | 不可の主な理由 |
|---|---|
| R1〜R6 | 制約が散文にしかなく、実装者が値を発明して幾何が壊れる |
| R8 | 修正した値が、そもそも意図した効果を持たない |
| **R9〜** | **修正は効くが、その値から導出されていた別の値が追随していない** |

R9で最も重い欠陥は私が作った。ai_biz_pitch の `base_caption` を動かしたとき、
それを分母にしていた4roleを1つも追随させていない。
しかも `promo_cta_banner` の `size.height 720` という**寸法自体**が
旧 `base_caption` からの導出だった。**座標だけでなく寸法も派生値である。**

### 検証で分かった、このスキル固有の落とし穴

1. **座標だけ直しても再現しない。** 導出に使った寸法を `size` に書かないと、
   実装者が別の寸法を発明して衝突が復活する（ai_biz_pitch / startup で実証）
2. **幅だけ縛ると悪化する。** 行数が増えて侵入量が倍になる（5スタイルで再現）
3. **`max_chars` は行数を止めない。** 9字制限でも折り返せば2行になる
4. **散文と構造化フィールドの非同期が最大の再発源。** 座標を直しても
   z_order_policy / apply_notes が旧値のままだと、そちらを信じた実装者が退行を再現する
5. **QCの緑は目視の代替にならない。** 動画レイヤーは検査対象外、
   グロー/ぼかしはalpha閾値ですり抜け、境界1フレームは時間分解能の外
6. **双子の片割れを取り残す。** position・font・max_chars・z_order まで一致する
   role が2つあるとき、片方だけ直すと lint も目視も通ってしまう
   （ai_biz_pitch の shock/positive、cinematic の sidebar[A2]/[A3] で実証）
7. **影を数え忘れる。** ドロップシャドウは右下+12px・左上−3px。
   R8で見つかった境界解7件のうち5件が「影を数えていない導出」だった
8. **検査自身の絞り込みが検査の目的を殺す。** R8で lint のバグを4件見つけたが、
   4件とも「その欠陥を捕まえるために作った検査が、絞り込みのせいで
   その欠陥を見逃していた」という同じ形だった
