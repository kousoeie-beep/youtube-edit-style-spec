# APIキーの差し替え口

**このファイルは何を扱うか**: `.env` の正本置き場・読み込み方・非出力規律、キー種別ごとの機能解禁条件、APIパス実証（ASR精度・Gemini設定・Veo不可・True Peak・APFS制約）で確定した制約。
**いつ読むか**: 実行開始時（APIキーの有無で処理経路が変わるため毎回の起動時に確認）。キーを使う生成・ASR・ナレーション工程に入る前。

- **配置状況（2026-07-25確認）**: OPENAI / GEMINI / ELEVENLABS の3キーが配置済み。APIパスは `DJI_0029_api`（run-05）でフルスタック実証済み
- `OPENAI_API_KEY` あり → ASRを gpt-4o-transcribe / whisper-1 優先（精度・速度とも向上。ローカルwhisperの複数パス照合は維持し、APIパスを主軸に置き換える）、**サムネ・挿入画像は `gpt-image-2` を指定**（こうすけ指定・2026-07-10アカウントで利用可能確認済み。旧gpt-image-1系は使わない）
- `GEMINI_API_KEY` あり → 整文・編集判断・B-roll企画を Gemini に（基準プリセット氏のクロス検証構成）。Veo B-roll生成は課金有効プロジェクトのキーが必要＋**生成本数は仕様書の「必要箇所だけ」原則を厳守（コストの支配項）**
- `ELEVENLABS_API_KEY` あり → ナレーション生成解禁
- キーなしでも編集の核心（カット/字幕/テロップ/音声/サムネ構成）は完動（パイロット4本で実証）

### APIパス実証で確定した制約（DJI_0029_api run-05・2026-07-13。次回実行時に必ず踏襲）

- **精度の定量効果**: ローカル3パス＋`whisper-1` APIの4パス単語照合で、多数決一致語が **338/400(84.5%) → 365/400(91.25%)** に改善、要文脈裁定語が 62→35 に減少。APIパス追加の効果は実測で裏付け済み
- **`gpt-4o-transcribe` は単語タイムスタンプ非対応**（`timestamp_granularities` は `whisper-1` 専用）。**時刻が要るパスに使ってはいけない**。テキスト品質のクロスチェック用途に限定し、単語タイムスタンプは `whisper-1` から取る
- **Gemini呼び出しは `maxOutputTokens=32768` ＋ `thinkingConfig.thinkingBudget=2048` が必要**。8192では応答が `MAX_TOKENS` で途中切断される（実測）
- **LLMの裁定は鵜呑みにせずExecutorが検証する**（run-05でGemini提案の却下3件・復元1件が発生）:
  ①全パス不一致の固有名詞をGeminiが推測表記→**却下**（「推測で字幕を作らない」規則）②言い直し区間の復元提案→**却下**（Gemini自身の書き起こしと自己矛盾）③オチ前の間の削除提案→**却下**（仕様書の「残す対象」に該当）④Gemini入力が単一タイムラインで末尾欠落→gpt-4o-transcribeのクロスチェックで**復元**。裁定の採否は `transcript.json` に記録する
- **Veo B-rollは現状使用不可**: `veo-3.1-fast-generate-preview` は HTTP 429 `RESOURCE_EXHAUSTED`（当該プロジェクトで課金・クォータ未有効化）。同一キーのGemini text APIは正常動作するため、キー無効ではない。**B-roll生成を前提に計画を組まない**
- **True Peakは最終ファイルを直接再測定する**: `alimiter` に target=-1.0dB を指定してもAAC再エンコード後は実測がそれより甘くなる。`aresample=192000`→`alimiter(level=false, limit=-2.5dB)`→`aresample=48000` ＋ `aac_at` で実測 **-1.74 dBTP**（I=-14.56 LUFS）を達成。**フィルタチェーン内のloudnorm summaryだけを信用すると本番不良を見逃す**
- **APFSクローン（`cp -c`）は当環境で機能せずフルコピーになる**（run-05でディスクを1.9GBまで圧迫）。素材はコピーせず **ffmpegから直接参照する方式**を既定にする
