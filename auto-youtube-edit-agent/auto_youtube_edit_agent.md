# Auto YouTube Edit Agent

素材を入れるだけで、YouTubeの本編（長尺）とShortsの両方を自動編集するためのマスター指示書。
このMDをClaude Code、Codex、または動画生成パイプライン実装エージェントに渡して実行する。

このツールはShortsの短尺編集に限定しない。10分以上の解説動画、チュートリアル、対談、実演、レビューなど、YouTube本編の長尺編集を第一級のユースケースとして扱う。長尺で必要になる章構成、発音同期字幕、ナレーション、グラフ/表、背景映像、イントロ、サムネイルまで、このエージェントができることはすべて自動生成する。

想定コマンド:

```bash
/chaen-youtube-edit <素材動画/音声/画像...> --script <台本.md optional> --mode auto --out ./dist
```

例:

```bash
/chaen-youtube-edit 冒頭.MOV 本編.mp4 台本.md --mode youtube-short --out ./dist/episode_001
```

## 目的

入力素材から以下を自動生成する。長尺本編でもShortsでも同じパイプラインで対応する。

- 無音、噛み、言い直し、長すぎる間、不要シーンを自動カットした完成動画（本編/Shorts両対応）
- 発音・発声に忠実に同期した日本語字幕（実際に聞こえた音の切れ目、抑揚、強調に合わせる）
- タイトル、章タイトル、アイコン、ロゴ、ツールカード、強調テロップ
- イントロ（冒頭のブランド提示/フック演出）とアウトロ（終端カード、CTA、次動画誘導）
- 指示または内容に応じたグラフ、表、図解、数値ビジュアルの生成と挿入
- 必要箇所だけのB-roll/背景映像生成と挿入
- ナレーション生成（追加解説、要約、章導入、不足箇所の補い）とBGM/SFX、音量統一
- サムネイル5案、タイトル案、説明文、チャプター、固定コメント
- YouTube公開後の改善用分析メモ

原則として、素材と指示から**エージェントが実行可能なことはすべて行う**。字幕だけ、カットだけで止めず、その動画を「そのまま公開できる完成品」に近づけるために必要な要素（字幕、テロップ、イントロ、アウトロ、グラフ、表、ナレーション、背景映像、BGM、サムネ、公開パック）を、素材と目的に合う範囲で自動的に補う。実行できなかった要素は理由を`edit_log.md`に必ず残す。

## 基本方針

1. まず内容を理解する。素材の見た目、音声、台本、目的を解析してから編集する。
2. 字幕は発音・発声ベース。実際に聞こえた音、切れ目、抑揚に合わせ、聞こえていないことを字幕にしない。
3. 余分な編集を足さない。視聴維持、理解、クリック率に効くものだけ入れる。
4. B-roll/背景映像は説明を具体化するために使う。雰囲気だけの映像は入れない。
5. 生成AI映像に文字を描かせない。文字、数字、グラフの数値は編集側のテロップ/図解で載せる。
6. 動画完成前にサムネを作らない。完成動画の最重要フレームと訴求から作る。
7. イントロは短く、結果/フックを妨げない。長いブランドアニメを冒頭に置かない（詳細は「イントロ/アウトロ生成」）。
8. グラフ・表は指示があれば必ず、指示がなくても数値・比較・手順・構成の説明があれば内容に応じて挿入する。捏造した数値は出さない。
9. ナレーションや背景映像など追加要素は、理解と維持に寄与する場合のみ足す。埋めるためだけに足さない。

## 入力

対応する入力:

- 動画: `.mp4`, `.mov`, `.m4v`
- 音声: `.wav`, `.mp3`, `.m4a`, `.aac`
- 台本: `.md`, `.txt`
- 画像/ロゴ/参考: `.png`, `.jpg`, `.jpeg`, `.webp`
- ブランド指定: `brand.md`, `style.md`, `thumbnail_reference/`

入力が複数ある場合、各素材に役割を割り当てる。

- `intro`: 冒頭、挨拶、フック
- `main`: 本編、解説、デモ
- `screen`: 画面収録、実演
- `proof`: 結果、比較、証拠
- `broll`: 既存B-roll
- `closing`: まとめ、CTA

## 出力

必ず以下を生成する。

```text
dist/
  final_1080p.mp4                   # 長尺本編（16:9）
  final_short_9x16.mp4              # 短尺の場合、または長尺からの切り抜き
  captions.srt
  captions.ass
  transcript.json
  edit_plan.json
  broll_plan.json
  intro/
    intro.mp4                       # 生成したイントロ（0.8-3秒）
    outro.mp4                       # 生成したアウトロ/エンドカード
    intro_plan.json                 # イントロ/アウトロの構成と根拠
  graphics/
    chart_01.png                    # グラフ（透過PNGまたは連番）
    table_01.png                    # 表
    graphics_plan.json              # 各図表の挿入位置、データ出典、根拠
  narration/
    narration_script.md             # 追加ナレーション台本
    narration_01.wav                # 生成した音声
    narration_plan.json             # 挿入位置、目的、声設定
  audio_mix_report.md
  thumbnail_01.png
  thumbnail_02.png
  thumbnail_03.png
  thumbnail_04.png
  thumbnail_05.png
  youtube_marketing_pack.md
  edit_log.md
```

生成できなかった要素（例: グラフ用の数値が素材に無い、TTS APIが無い等）は空フォルダを残さず、`edit_log.md`に「未生成の要素と理由」を明記する。`final_1080p.mp4`も例外ではない。素材が単一の短尺クリップで長尺版に意味がない場合は生成せず、その旨を`edit_log.md`に記録する。

## API/モデル選択

環境変数:

```bash
OPENAI_API_KEY=
GEMINI_API_KEY=
ELEVENLABS_API_KEY=
```

推奨ルーティング:

- 文字起こし: ローカルWhisperを優先。精度不足ならOpenAI `whisper-1`、リアルタイム用途ならOpenAI realtime transcription系を使う。単語タイムスタンプは字幕の発音同期に必須なので必ず取得する。
- 編集判断、構成整理、カット理由、B-roll企画、グラフ/表の設計、ナレーション台本: Gemini APIまたは高性能LLM。
- 画像生成、サムネ素材、アイコン、背景カード、イントロ/アウトロ用の背景ビジュアル: OpenAI GPT Image系。最新の利用可能モデルを確認し、2026-07-07時点ではOpenAI docs上の `gpt-image-2` を優先候補にする。
- グラフ/表の描画: 数値の正確さが要るため生成AI画像で描かせず、Python（matplotlib/plotly）またはHTML/CSS/SVGでデータからレンダリングする。デザインだけAIに寄せてもよいが数値・軸・ラベルはコード側で確定する。
- B-roll/背景映像生成: Gemini API経由のVeo 3.1/3.1 Fast。3-8秒の短い補助映像だけ生成する。
- イントロ/アウトロ: 静止画/ロゴ＋モーション（ffmpegのアニメーション、ズーム、フェード）で構成。背景素材のみVeoやGPT Imageを使い、文字はテロップで載せる。
- ナレーション/TTS/声質変換: ElevenLabs。本人の声をクローンする場合は明示許諾がある時だけ使う。ナレーションは元発話と声質・トーンを揃える。
- レンダリング: `ffmpeg` + Python。字幕はASSで焼き込み、最終MP4はH.264/AAC。

APIがない場合のフォールバック:

- B-roll/背景映像生成不可: 既存素材、静止画、図解カード、画面キャプチャ、ゆっくりパン/ズームで代替。
- TTS不可: 追加ナレーションは生成せず、元音声を整音して使用。台本だけ`narration_script.md`に残す。
- GPT Image不可: HTML/CSS/CanvasまたはPillowでサムネ、イントロ背景、図表を自動生成。
- グラフ描画ライブラリ不可: HTML/CSS/SVGの表・棒グラフで代替し、ffmpegで静止画化して挿入。

## 編集モード判定

素材と台本から自動判定する。

- `youtube-short`: 15-90秒、9:16、冒頭1-3秒のフック重視
- `youtube-long`: 5分以上、16:9、章構成、証拠、デモ重視
- `auto`: 入力素材から最適化。長尺からShorts切り抜きも同時生成してよい

出力比率:

- Shorts: 1080x1920, 30fps, H.264, AAC
- 通常YouTube: 1920x1080, 30fps or source fps, H.264, AAC

## 全体ワークフロー

### 1. 素材解析

実行すること:

- `ffprobe`で解像度、fps、長さ、音声チャンネル、音量を取得。
- 動画から代表フレームを抽出し、顔、画面収録、スライド、黒画面、手ブレ、重複を検出。
- 素材の向き（横倒し撮影、回転メタデータ、縦横比とターゲット比率の不一致）を検出する。横倒し素材は正しい向きに回転補正する。縦(9:16)出力で素材が画面いっぱいにならない場合は、同素材をぼかし拡大した背景の上に正しい向きの映像を重ねる（ブラー背景フィル）。補正内容は`edit_plan.json`の`transform`に記録する。
- 台本がある場合は台本と音声を照合し、話していない台本文は字幕にしない。
- 複数素材は役割を推定し、`edit_log.md`に記録。

### 2. 文字起こし

日本語音声として処理する。

通常:

- 音声をmono 16kHzに変換。
- ローカルWhisperまたはOpenAI `whisper-1`で単語タイムスタンプつき文字起こし。
- `transcript.json`に保存。

音声が不明瞭な場合:

- raw、enhanced、denoisedの3種類を作る。
- 複数パスの文字起こしを比較。
- 確信できない語は `不明` または `uncertain_terms` に記録。
- 推測で字幕を作らない。

### 3. 自動カット

カット対象:

- 0.45秒以上の無音。ただし感情、考える間、オチ前の間は残す。
- 「えー」「あの」「まあ」「なんか」などのフィラー。ただし話し方の自然さが消える場合は一部残す。
- 言い直し、重複説明、準備中、待ち時間、読み込み画面。
- 台本から外れた独り言、ミス、確認音、操作迷い。
- 黒画面、画面共有ミス、不要なブラウザ/プレイヤーUI。

残す対象:

- 冒頭の結論、違和感、驚き、問題提起。
- デモ結果、比較、失敗からの修正、視聴者が納得する証拠。
- オチ前の短い間、反応、表情。

カット判断はJSONで保存する。

```json
{
  "cuts": [
    {
      "start": 12.34,
      "end": 15.20,
      "reason": "long_silence_and_retake",
      "risk": "low"
    }
  ],
  "kept_pauses": [
    {
      "start": 40.10,
      "end": 40.85,
      "reason": "payoff_before_reveal"
    }
  ]
}
```

### 4. 構成

Shorts:

- 0-2秒: 結果、違和感、強い問い、完成物を先に見せる。
- 2-8秒: 状況説明。
- 8-20秒: 実演、証拠、変化。
- 20秒以降: 回収、学び、軽いCTA。

長尺:

- 0:00-0:03: 結論テロップ。
- 0:03-0:15: 誰向けか、何が解決するか。
- 0:15-0:40: 今日見せる結果。
- 0:40-1:30: 章予告と信頼形成。
- 本編: 概念、実演、結果、人間の確認、まとめ。
- 終盤: 3-5点の要約と一つのCTA。

## 字幕/テロップ

字幕（発音・発声同期）:

- 発話同期。単語タイムスタンプを使い、字幕の表示・切替を実際の**発音の開始/終了**に合わせる。
- 区切りは息継ぎ、間、語尾の切れ目、意味のまとまりで決める。発話が途切れていないのに字幕を割らない。
- 抑揚と強調に合わせる。話者が強く言った語、伸ばした語は表示タイミングを合わせ、必要なら強調テロップ側で拾う。
- 実際の発音を優先する。台本と違う言い回し、言い直し後の確定版、方言/口語の縮約（「〜してる」等）は聞こえた通りに書く。
- 数字、モデル名、専門用語は聞こえた読みと正しい表記を両立させる。読みが不確かな語は`uncertain_terms`に記録し、断定しない。
- 1字幕あたり最大2行。1行は日本語13-18文字程度を目安。長尺では読み速度（1秒あたり約7-9文字）を超えない範囲で分割する。
- 文意より正確性を優先。
- 画面下中央、白太字、黒縁または強シャドウ。長尺で話者やUIが下部にある場合は位置を退避する。
- カラオケ的な発音追従（ASSの`\k`タグ等）は、教材・歌・early access的なテンポ強調が有効な時だけ使い、通常の解説では使わない。

強調テロップ:

- 黄色 + 黒縁。
- 重要語、モデル名、意外な主張だけ。
- 1.0-2.5秒表示。
- 通常字幕と同じ文言を重複させない。

大見出し/モデル名リビール:

- 0.8-1.8秒。
- 中央または下中央。
- 白/水色/淡いグラデーション + 太い縁 + 軽いグロー。
- 1トピック1回まで。

テロップ/オーバーレイのスタイル名は`edit_plan.json`の`overlays`に以下のenumで記録し、レンダリング側のASSスタイル定義（`Subtitle`/`Hook`/`Emphasis`/`Label`/`Reveal`）と一対一対応させる。

```json
{
  "overlays": [
    {
      "start": 0.0,
      "end": 2.4,
      "text": "駅前でまさかの遭遇",
      "style": "Hook"
    },
    {
      "start": 6.35,
      "end": 8.7,
      "text": "新宿まで来たぞ",
      "style": "Emphasis"
    }
  ]
}
```

- `Hook`: 冒頭フック用の1行見出し。動画開始直後、最も強い訴求のみ。
- `Emphasis`: 本文中の強調テロップ（黄色+黒縁ルールと同じ配色）。
- `Reveal`: 大見出し/モデル名リビール。
- `Label`: 右上テーマラベルや番組ロゴなど、常時/長時間表示される小さな識別テキスト。

スクリーンショット風カード:

- 背景: `#070814` または黒に近い濃紺。
- カード: 白または濃紺、角丸8-14px、細い金線/白線。
- 見出し: 太字白、日本語はNoto Sans JP/源ノ角ゴ。
- APIカード: 左にロゴ/アイコン、右に名称、下に用途説明。
- 画面下の章テロップ: 黄色 + 黒縁、例 `3 あとはスキルを使うだけ`。

## アイコン/タイトル配置

自動配置ルール:

- 左上: 小さな番組ロゴまたはシリーズ名。
- 右上: テーマラベル。例 `AI動画編集`, `Claude Code実演`, `Gemini API活用`。
- 中央: 重要モデル名、結論、数字。
- 下部: 発話字幕。口や重要UIを隠さない。

ロゴや商標:

- 公式ロゴを使う場合は権利とガイドラインを確認。
- 不明な場合は抽象アイコンで代替。
- GPT Imageで商標ロゴを生成しない。既存ロゴの改変もしない。

## B-roll生成と挿入

B-rollを入れる条件:

- 口頭説明だけでは抽象的。
- ツール名、API、ワークフロー、結果物が話題に出た。
- 視聴者の理解を助ける証拠、例、比喩、比較が必要。
- 同じ画が8秒以上続き、情報量が落ちる。

B-rollを入れない条件:

- 話者の表情が重要。
- 画面収録の操作が重要。
- 字幕や説明と競合する。
- 生成映像が雰囲気だけで内容を説明しない。

生成尺:

- Shorts: 1.5-4秒
- 長尺: 3-8秒

Veo用プロンプト方針:

- 8-20語程度。
- 動きだけを具体化する。
- 文字、UI、ロゴ、ブランド名は生成しない。
- 例: `Slow push-in on a tidy desk where automation steps assemble as physical cards, soft studio light`

B-roll計画JSON:

```json
{
  "items": [
    {
      "insert_at": 38.2,
      "duration": 4.0,
      "purpose": "Gemini APIが編集判断を担当する説明を具体化",
      "model": "veo-3.1-fast",
      "prompt": "Camera glides over labeled workflow cards connecting transcript, cuts, captions, and final video",
      "fallback": "static_workflow_card"
    }
  ]
}
```

B-rollが不要と判断した場合も`broll_plan.json`は必ず生成し、`items`を空配列にした上で`decision`に判断理由を残す。「生成しなかった」と「判断せず忘れた」を区別するため、このファイルの省略は禁止する。

```json
{
  "items": [],
  "decision": "24.7秒の人物中心Shortsなので、生成B-rollは入れず、回転補正・テンポ・字幕・強調テロップを優先した。"
}
```

## イントロ/アウトロ生成

長尺本編にはイントロとアウトロを生成する。Shortsでは原則イントロを付けず、冒頭フックをそのまま使う。

イントロ方針:

- 冒頭は「結果、違和感、問い、完成物」を先に見せる。長いブランドアニメで視聴者を待たせない。
- ブランド提示は結果フックの**あと**、または結果フックに重ねる小さなロゴ/ローワーサードで行う。
- 生成するイントロは0.8-3秒。番組ロゴ、シリーズ名、今日のテーマ、1フレーズの約束だけ。
- 背景は生成ビジュアル（Veo/GPT Image）＋ffmpegのズーム/フェード/スライド。文字は必ずテロップで載せる。
- 同一シリーズでは一貫したイントロテンプレートを使い、テーマ文字だけ差し替える。

アウトロ方針:

- 3-8秒。要点1行、CTA1つ（登録/次動画/コメント誘導）、次動画サムネ枠、固定リンク。
- エンドスクリーン用に最後の10-20秒は要素を置ける余白を残す。
- 音楽は本編より控えめにフェードアウト。

イントロ/アウトロ計画JSON:

```json
{
  "intro": {
    "duration": 2.4,
    "style": "logo_reveal_over_result",
    "theme_label": "AI動画編集",
    "promise": "素材を入れるだけで本編が完成",
    "background": "veo_or_gpt_image",
    "fallback": "static_gradient_zoom"
  },
  "outro": {
    "duration": 6.0,
    "cta": "次の動画で公開パック生成を実演",
    "endscreen_reserved_seconds": 18
  }
}
```

## グラフ/表/図解の生成と挿入

指示があればグラフ・表を必ず挿入する。指示がなくても、数値、比較、割合、推移、手順、構成、Before/Afterが語られたら内容に応じて図表化する。

判断:

- 数値・比較・推移がある → グラフ（棒/折れ線/円/比較バー）。
- 項目対項目の対応、仕様、価格、機能一覧 → 表。
- 手順、フロー、関係性 → 図解/フローカード。
- 単一の強い数字 → 大きな数値テロップ（グラフにしない）。

データの扱い:

- 数値は素材（発話、台本、画面、提供データ）に実在するものだけ使う。**捏造・推測した数値を出さない。**
- 出典が曖昧な数値は図表にせず、テロップで「概算」と明示するか省く。
- 各図表はデータ、出典、挿入位置を`graphics_plan.json`に記録する。

描画:

- 数値の正確さのためグラフ・表は生成AI画像で描かせない。Python（matplotlib/plotly）またはHTML/CSS/SVGでデータからレンダリングし、透過PNG/連番で出力。
- 配色・フォントは本編のテロップ規則に合わせる（濃紺背景`#070814`、白/水色見出し、Noto Sans JP）。
- グラフは発話に同期してアニメーション（棒が伸びる、線が描かれる）させると理解と維持が上がる。過度な演出はしない。
- 挿入尺: 図表を読む時間を確保する。長尺は4-10秒、Shortsは1.5-4秒。ナレーション/字幕で要点を1行添える。

## 背景映像

素材が静的（画面収録の静止、話者の据え置きショット、音声のみ区間）で情報量が落ちる箇所には背景映像を補う。

- 話題に対応する抽象/実写風の背景をVeoで生成、またはB-roll・静止画のゆっくりパン/ズームで代替。
- 音声だけの区間（ナレーション、電話越しの声など）には、内容に沿った背景映像＋字幕＋関連図表を重ねて画面を保たせる。
- 背景映像は主役の説明を邪魔しない明度・動きに抑える。文字は生成させず編集側で載せる。
- 選定・生成の基準はB-rollと同じ（雰囲気だけの映像は入れない）。計画は`broll_plan.json`に統合してよい。

## 音声処理

順番:

1. クリップ間の音量差を整える。
2. ノイズがある場合のみ軽く除去。
3. 声にハイパス80-100Hz、軽いコンプレッサー、リミッター。
4. BGMを入れる場合は声を優先してダッキング。
5. SFXはテロップや転換点だけ。
6. 最終ラウドネスをYouTube向けに統一。

目安:

- Integrated loudness: -14 LUFS前後
- True peak: -1.0 dBTP以下
- 声が最優先。BGMやSFXが発話を隠したら失敗。

`audio_mix_report.md`には処理前の音量に加えて、処理後に実測したintegrated loudness (LUFS)とtrue peak (dBTP)を必ず記載する。目安との差分が大きい場合は理由を書く。

SFX:

- 通常字幕には入れない。
- 強調テロップ、モデル名リビール、章切替、結果表示だけ。
- 1.2秒以内に複数SFXを重ねない。

## ナレーション生成

元発話だけで不足する箇所を、生成ナレーションで補う。埋めるためだけには足さない。

足す条件:

- 章の導入・橋渡し（「ここからは実際に動かします」）。
- 画面だけで進む区間の説明（無言の操作、読み込み、結果表示）。
- 要約・まとめ（長尺終盤の3-5点整理）。
- 発話が不明瞭で作り直したいが再収録できない箇所（内容は変えない）。

方針:

- 声質・トーン・話速を元話者に近づける。本人の声クローンは明示許諾がある時だけ。許諾が無ければ別ボイスと明示。
- 台本は`narration_script.md`に残し、生成音声は`narration/`に出力。挿入位置・目的を`narration_plan.json`に記録。
- ナレーション区間も発音同期字幕を付ける。
- 元発話とナレーションのラウドネス・質感を揃え、切替を不自然にしない。
- 事実は素材に基づく。ナレーションで新しい主張・数値を捏造しない。

ナレーション計画JSON:

```json
{
  "items": [
    {
      "insert_at": 210.5,
      "type": "chapter_bridge",
      "text": "ここからは実際にコマンドを実行して、字幕とサムネまで自動生成させます。",
      "voice": "match_speaker",
      "consent_for_clone": false,
      "fallback": "keep_original_audio_only"
    }
  ]
}
```

## サムネイル5案

完成動画から一番強い約束を抽出し、5方向を同時に作る。

### 案1: 結果約束型

- 視聴後に得られる結果を大きく見せる。
- 例: `素材だけで完成動画`
- 背景は完成画面、編集済みタイムライン、生成物。

### 案2: 問題解決型

- 視聴者の悩みを短く刺す。
- 例: `編集、まだ手作業?`
- 表情、失敗画面、Before/Afterを使う。

### 案3: 権威/新規性型

- API、モデル、最新性、ワークフローを見せる。
- 例: `Gemini x Veo x GPT Image`
- APIカード、モデル名、ツール構成を整理して見せる。

### 案4: 証拠/数字型

- 変化量、短縮率、件数、Before/Afterなど検証できる数字を大きく見せる。
- 例: `24日→5日`
- 背景は完成物、グラフ、比較画面。数字は編集側で載せ、生成画像に描かせない。

### 案5: 人物/感情型

- 視聴者がクリック前に感情を読める表情、手元、リアクションを使う。
- 例: `これ本当に自動?`
- 顔出し素材がない場合は、完成動画の最も驚きが伝わるフレームや生成した人物ビジュアルを使う。

サムネ規則:

- 文字は最大3-6語。
- スマホの小さい表示で読める太字。
- 顔、結果物、強いコントラストのどれかを必ず入れる。
- タイトルとサムネで同じことを重複しすぎない。サムネは感情/結果、タイトルは具体性を担当。
- 5案を保存し、公開時はCTR仮説が最も違う3案をYouTube StudioのA/Bテスト候補に選抜する。

## YouTubeマーケティング知見

編集前にパッケージを仮決めする。

- 誰が見るか。
- 何を得るか。
- なぜ今見るか。
- クリック後の最初の3秒で約束が回収されるか。

2026運用ルール:

- Shortsは発見装置。長尺は信頼、教育、成約に使う。
- Shortsと長尺を分断せず、同じテーマを短尺フック、長尺解説、切り抜きで展開する。
- 冒頭にブランドロゴ長尺イントロを置かない。まず結果、違和感、完成物、問題を見せる。
- タイトル/サムネ/冒頭の約束を一致させる。クリックベイトで維持率を落とさない。
- サムネとタイトルは最大3パターンでテストし、クリック率だけでなく総再生時間/維持で勝者を選ぶ。
- 視聴者のリテンション低下点を次回の編集ルールに反映する。

分析ルール:

- 0-3秒で落ちる: フックが弱い、結果が遅い、状況説明が長い。
- 10-30秒で落ちる: 約束と本編のズレ、テンポ不足、証拠不足。
- 中盤で落ちる: 同じ画、抽象説明、進展不足、B-roll不足。
- CTRが低い: タイトル/サムネの約束が弱い。
- CTRは高いが維持が低い: パッケージと中身がズレている。

## 品質チェック

レンダリング前:

- 字幕が発音・発声（実際の音の切れ目と抑揚）に同期している。
- 不確かな文字起こしを断定字幕にしていない。
- 強調テロップが字幕と重複していない。
- 顔、口、重要UIを字幕やカードで隠していない。
- B-roll/背景映像が説明内容に対応している。
- グラフ・表の数値が素材に実在し、軸・ラベル・単位が正しい。捏造数値がない。
- グラフ・表の表示尺が読むのに十分で、要点が1行添えられている。
- イントロが長すぎず、冒頭で結果/フックを妨げていない。アウトロにエンドスクリーン余白がある。
- 生成ナレーションが元発話と質感・音量で揃い、新しい主張を捏造していない。声クローンは許諾済みか別ボイス明示。
- SFXが発話を邪魔していない。
- 音量がクリップ間で揃っている。処理後の実測LUFS/dBTPが`audio_mix_report.md`に記載されている。
- 横倒しや向きが不正な素材が正しく回転補正され、縦(9:16)出力で不自然な余白がない。
- 冒頭3秒で動画の価値が伝わる。
- 長尺はチャプターが内容と一致し、各章の頭で何を得るか分かる。
- サムネ5案がそれぞれ違う訴求になっている。
- 生成できなかった要素の理由が`edit_log.md`に記録されている。

レンダリング後:

- `ffprobe`で尺、解像度、fps、音声を確認。
- 代表フレームを10枚以上書き出し、テロップの切れ/重なりを確認。
- スマホサイズ相当で字幕とサムネを確認。
- 最終MP4を最初から最後までプレビューする。

## 実装エージェントへの最終指示

あなたは動画編集ディレクター兼自動レンダリングエンジニア。
このMDのルールに従い、入力素材を解析し、YouTube本編（長尺）とShortsの両方で、カット、発音同期字幕、テロップ、イントロ/アウトロ、グラフ/表/図解、B-roll/背景映像、ナレーション、音声処理、サムネ、YouTube公開パックまで生成する。
原則として、その動画を完成品に近づけるためにあなたが実行できることはすべて行う。字幕やカットだけで止めない。
途中で不確かな字幕、権利不明のロゴ、本人許諾のない声クローン、出典不明の数値が発生した場合は、自動で代替案を使うか省き、`edit_log.md`に理由を残す。
最終出力は、視聴者がスマホでも一目で理解でき、長尺では最後まで、Shortsでは冒頭から、YouTube上でクリック後の約束をすぐ回収できる動画にする。
