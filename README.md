# 編集スタイル仕様 — 引き継ぎ一式

**動画の編集スタイル15本を、機械可読な仕様（yaml）として書いたもの。**
2026-07-31 時点。引き継いだ人がやるのは **「チューニングの周回を回すこと」** です。

このREADMEだけで着手できるように書いてあります。前提知識は不要です。

---

## 1. なぜこれがあるのか

「この動画、○○風に編集して」と頼むとき、その「○○風」を**文章で説明しても再現されません**。
実際に11周やって分かった原因はこれでした。

> **再現できない原因は座標ではなく、制約が散文にしか無いこと。**
> `max_chars` / `size` / `font_px` / 排他 / 変種 が空欄だと、
> **実装者がその値を発明して幾何が壊れます。**

だからこのリポジトリは「スタイルを言葉で説明する文書」ではなく、
**機械が検査できるフィールドの集合**です。散文は補足であって根拠ではありません。

## 2. できること / できないこと（ここを誤解しやすい）

**先に結論**: 動画編集そのものは**動いています**。ただし**このリポジトリだけでは動画は作れません**。
別物なので分けて書きます。

### 動画編集は動いている（このリポジトリの外の話）

このスタイル定義を使う編集エンジンは、**パイロット3本を完走済み**です。

| 項目 | 実測 |
|---|---|
| 出力 | 長尺＋Shorts＋字幕＋サムネ5案＋公開パック(dist/) |
| QC | ○10-15 / △3-5 / **×0** |
| 音 | **-14 LUFS 達成** |
| カット | 4〜36% を自律選択（99秒 → 82.11秒） |
| 自己修復 | レンダリング後QCで口元被り字幕を自分で直した |

**素材を渡すだけで人手ゼロで完成します。** そこは疑わなくて大丈夫です。

### このリポジトリに入っているもの / いないもの

| | |
|---|---|
| ✅ **編集の一次指示書** | `auto-youtube-edit-agent/`（**2026-07-31 に統合**。以前は別リポジトリだった）。**動画をどう編集するかの大元** |
| ✅ **スタイル定義** | 15本＋静的検査26項目＋被りQC＋検証プロトコル＋計測ツール |
| ⛔ 入っていない（意図的） | 各周の使い捨てレンダラ（→ §6） |
| ⛔ 入っていない | 実素材（動画・音声・台本）・フォント実体・APIキー |

**⇒ 仕様は全部そろっています。足りないのは素材だけです。**
（APIキーは無くても編集の核心＝カット/字幕/テロップ/音声/サムネ構成は完動します）

### 「完成していない」の意味

READMEが「まだ完成していない」と書いているのは、**スタイルの再現精度**の話です。

> 15本中、**yamlだけを読んで同じ絵が作れるのは7本**。

**動画が作れないという意味ではありません。** 作れますが、
「○○風にして」と言ったときに**その"風"が毎回同じ絵になる保証が7本ぶんしかない**、
という状態です。それを15本に上げるのがこの引き継ぎの目的です。

## 3. いまの状態（数字）

```
lint            違反 0 / 申し送り 10          ← 26項目（違反ゲート11＋申し送り15）
再現できた      15本中 7本
未検証          7本（修正直後。一番危ない状態）
検証中          1本
```

**フィールド充足率（全110 role）**

| フィールド | 充足 | 意味 |
|---|---|---|
| `size` | 61% | 要素の外形（フチ・影込み） |
| `variant` | 47% | どの変種で使うか |
| `max_chars` / `font_px` | 35% | 1行の字数上限 / フォントサイズ |
| `stroke_px` | 13% | フチ幅。**袋文字ではこれが無いと size が決まらない** |

**この空欄が残件そのものです。** 埋めるほど再現率が上がります。

## 4. 30秒で環境を確認する

必要なもの: **Python 3 + `uv`** / **ffmpeg・ffprobe** / **NotoSansJP-Bold, -Regular**

```bash
cd youtube-edit-style-spec
uv run --with pyyaml python3 styles/lint.py
```

`クリーン / 申し送り N 件` と出れば通っています。
（`申し送り` は終了コードに影響しません。次周の宿題です）

## 5. 1周の回し方

**正本は [`verify/PROTOCOL.md`](youtube-edit-style-spec/verify/PROTOCOL.md)。** 要約:

1. **yaml のフィールドだけを読んで、対象スタイルをゼロから実装する**
   （散文は読んでよいが、実装の根拠には使わない）
2. 25秒のクリップをレンダリングする
3. `overlap_qc.py` を通す（本編と対照窓で config を分ける）
4. `verify/measure.py --boxes` で宣言矩形、`--work` で実インクを測る
5. フレームを**最低6点**目視する
6. **可 / 不可** を判定する（基準は PROTOCOL §4。**「ほぼ可」は書かない**）
7. 修正は `verify/yamledit.py` の `set_field()` を通す（直接編集しない）
8. **`lint.py` で違反0を確認してから次の周へ**

**1周の目安**: 2スタイルで 30〜50分（レンダリング込み）。

## 6. なぜレンダラを渡さないのか

**検証の力は「yaml だけを読んだ別人がゼロから組み直す」ところにあります。**
共通のレンダラを渡すと、その再実装が消えて**検証が何も測らなくなります**。

過去11周ぶんの使い捨て実装（153本）も入れていません。毎周書き捨てが正しい形です。

## 7. 用語（これを知らないと報告書が読めません）

| 語 | 意味 |
|---|---|
| **role** | 画面上の1装置（字幕・名札・カード・ロゴ等）。yaml の `telop_layers` の1要素 |
| **変種 (variant)** | 同じスタイル内の別パターン。**変種が違えば同時表示されない**ので衝突を考えなくてよい |
| **箱 / インク** | **箱**＝`size` が定義する外形。**インク**＝実際に描かれたピクセルの範囲。**この2つは一致しません**（箱は中心対称、インクは影とグリフで非対称）。**導出は必ず箱基準で**行います |
| **派生値** | 他のroleの値から計算された値。**分母を動かしたら全部やり直し**が要ります |
| **対照窓** | 規約を**わざと破った**区間。破ると何が起きるかの記録。**本編と時間で分離**し、時刻を必ず明記します |
| **申し送り** | lint の警告。違反ではないが次周の宿題 |
| **可 / 不可** | 5条件のAND（発明値0 / QC exit 0 / 4辺とすきま16px以上 / 目視 / 宣言と実測の一致）。**1つでも欠けたら不可** |

## 8. 必ず踏む罠（先に読むと数時間得します）

1. **`max_chars` は行数を止めません。** 歯止めは `overflow_policy` にしかない。
   62字が「4行・各行17字以下・違反ゼロ」のまま画面外に95px出た実例があります
2. **`max_chars × max_lines` は総量の上限になりません。** 欧文は単語の切れ目でしか折り返せず、
   端数の切り捨ても効くので、`max_chars_total` を別に持ちます
3. **箱とインクを混同しない。** インク基準で16px確保しても、**宣言矩形では4px**になります
4. **影は右下+12px / 左上−3px**（`alpha>0` 基準）。QCの `alpha>10` では +8 / 0。
   **画面外の判定は `alpha>0` で見ます**
5. **QCの緑は目視の代わりになりません。** `layer_kind: video` の役は検査対象外、
   グロー/ぼかしは alpha 閾値ですり抜けます
6. **一括編集は必ずクォートしたヒアドキュメント**（`<< 'PY'`）で。
   `<< PY` だとコメント内のバッククォートがシェルに食われて**記述が消えます**（2回やりました）
7. **`/private/tmp` は消えます。** 作業物を置かないこと（道具を1つ失いました）

## 11. 引き継ぐ相手への一番の忠告

**規約を足したら、その周のうちに `lint.py` に検査も足すこと。**

検査の無い規約は、**書いた本人が翌周に破ります**。11周で何度も実演しました。
逆に、検査を書いた瞬間に既存の違反が10件20件と出てきます。それが正常です。

もう1つ。**「実測」と書くだけでは実測になりません。**
測った文字列・実幅px・字数の**3点セット**を書いてください。
同じ周に足した2つの定数で、**出所を書いた方だけが正しく、書かなかった方は実測を下回っていました。**
